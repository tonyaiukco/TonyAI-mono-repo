## Localisation and error codes

LP3-01 laid the foundation the remaining screens (LP4-04), onboarding (LP4-01) and reports (LP4-03) build on. Turkish UI copy lives **only** in the `tr` catalogue (CLAUDE.md's one exception); keys, code and docs stay English. Recipes: the [`localise-ui`](../../.claude/skills/localise-ui/SKILL.md) skill.

- **Framework.** [`use-intl`](https://next-intl.dev/docs/environments/core-library) 4 (next-intl's core, pinned) behind a client `I18nProvider` (`apps/web/components/i18n/`). Every page is a client component behind sign-in, so neither locale routing nor next-intl's server and extractor layers are used.
- **Which language.** `profiles.language` is the truth; the `tonyai-locale` cookie mirrors it for the first paint. The root layout resolves cookie → `Accept-Language` → English, and once `/me` answers, the profile wins (`LocaleSync`). The sidebar's switcher saves through `PATCH /me/preferences` (audited).
- **Catalogues.** `apps/web/messages/{en,tr}/<namespace>.json`, one file per namespace so parallel features do not collide: `common`, `nav` (app shell), `errors` (`codes.<ApiErrorCode>`), `numbers`, `periods` (`granularity.*`, `values.*` by canonical value), `categories` (by canonical value), `dataEntry`, `auth` (sign-in, forgot password, the emailed-link screens) and `users` (LP4-01), `reportingContext`, `dashboard`, `reports`, `boundary` (LP3-02, LP4-03); LP4-04 slice 2 adds `anomaly`, `bulkSubmit`, `bulkUpload`, `completeness`, `evidence`, `imports`, and three vocabularies keyed by canonical value — `recordStatus` (`label.*` for a badge, `inline.*` inside a sentence), `units` (`label.*`, `blocked.*`; English equal to `ACTIVITY_UNITS`) and `geography` (English equal to `GEOGRAPHY_LABELS`); PR B adds `emissions`, `targets`, `intensity` and the vocabularies `targetStatus`, `targetBasis` (`TARGET_STATUSES`/`TARGET_BASES` in `lib/vocabulary.ts`, exhaustive over the shared-types unions) and `intensityMetrics` (English equal to `INTENSITY_METRIC_META`'s labels; a metric's default unit stays the stored, language-neutral one), PR C adds `subsidiaries`, `review`, `audit` and the vocabulary `subsidiaryStatus` (by `SUBSIDIARY_STATUSES`; English lowercase as the screens always printed it, moved out of `dashboard.register.status`) and `periods.granularityInline` (a granularity inside a sentence); and grows `dashboard` and `common` (`notCalculated`/`noFactor` — the only words for a record with no figure now that `calculation-display`'s constants are gone — `loading`, `saving`, `cancel`, `tco2e`, `entity.*` — English equal to shared-types' entity phrases, which the generated report keeps — and `actor.*`). Shared words live in `common`; a count pair is `xxxOne`/`xxxMany`. A new screen adds its own namespace. A view module (`lib/*-view.ts`) words its sentences through the copy its screen passes — `{ t, locale }` (`ViewCopy`, `lib/i18n/view-translator.ts`), plus `useRecordWords()` where it names a status, period, category or activity type (`activity(category, type)`, from `dataEntry.activityTypes` for a type in the category's own list, `dataEntry.notSpecifiedLegacy` for `unspecified`, else the stored value; `categoryWithActivity` words "Refrigerants (R-410A)" for the review queue and sheet, uat2-review-shows-gas) — never an English literal; its spec passes `copyFor(namespace, locale)` from `lib/i18n/testing.ts`, so asserting English asserts the catalogue. A simple ICU argument prints a number as written (never grouped), so a count is passed through `formatNumber(n, locale)`. English is the source type; `messages.spec.ts` holds every locale to the same keys and ICU arguments, every registered error code to a sentence, and every canonical category and period to a label.
- **Error body.** Every API error carries `code` from the registry in `@tonyai/shared-types` (`API_ERROR_STATUS`): `{ statusCode, code, message, error?, params? }` plus a refusal's own fields (`coverage`, `failed`, …). `message` stays the English sentence (logs, older readers, e2e). Specific codes are thrown with `errorBody(code, …)` / `ResourceNotFoundError` (`apps/api/src/common/api-error.ts`); anything else gets its status's generic code from the exception filter, and DTO refusals answer `validation_failed`. **Every 5xx is `internal_error` with no cause in the body** (it goes to the logs and Sentry). A `*_not_found` code names the kind of thing, never why, and carries no params — another organisation's id and a missing one answer byte-for-byte the same (`tenant-isolation.int.spec.ts`). `params` carry exactly the keys their code declares (`API_ERROR_PARAMS`) — canonical values, never ids or caller text; the filter drops any other key, and all params when a code is downgraded. A declared key is either named in the code's sentence or is a **sentence selector** (`API_ERROR_SENTENCE_SELECTORS`): its value picks `errors.variants.<code>.<value>` when the catalogue has one, and the code's own sentence otherwise, and no sentence names it. The only selector is `variance_reason_required`'s `basis` (`history` or `ceiling`, BUG-R2-07 tier 3, 2026-11-13): a first period above its typo ceiling has no historical average to deviate from. A specific code always answers its own status; `bad_request` is the code of any 4xx without one of its own (405, 410, 422, …) and `internal_error` of any 5xx. **Stability:** a code is added, never renamed or reworded into another; a route may move from a generic code to a specific one, never from one specific code to another. LP4-04 slice 2 PR C (M3) moved the refusals a pilot user meets: the 404s of subsidiaries, locations, targets (`target_not_found`), intensity (`denominator_not_found`) and import batches (`import_batch_not_found`, `import_source_not_retained`, `import_source_missing`); the business-rule 400/409s of subsidiaries (`subsidiary_location_required`, `subsidiary_in_use` — with `SubsidiarySummaryDTO.blockerCounts`, the same refusal as facts), locations (`location_in_boundary`, `location_has_records`, `location_declared_during_delete`), period locks (`period_lock_value_invalid`, `period_records_*`, `period_already_locked`), targets, intensity, evidence (`evidence_file_*`, `evidence_record_not_editable`, `evidence_records_*`, `evidence_backs_locked_records`) and activity records (`record_period_invalid`, `record_not_editable/submittable/reviewable/approvable/voidable/rejectable` with the record's `status`); and the bulk upload's file-level refusals (`bulk_file_*`, `bulk_no_rows`, `bulk_too_many_rows`, `bulk_workbook_*`, `bulk_workbook_first_sheet_not_worksheet`). The role-only 403s, the per-row sentences and the refusals naming a cell or a caller's column stay generic. The server's English `message` is unchanged on every one. A DTO constraint may name its own domain code (`codedConstraint`, `apps/api/src/common/coded-validation.pipe.ts`): the pipe answers that code, with the field's sentence as `message`, only when it is the body's one refusal — today `activity_value_too_large` on the record and preview routes (LP4-04); otherwise `validation_failed`. Per-row outcomes keep their own vocabularies (`BULK_UPLOAD_ISSUE_CODES`, `BULK_SUBMIT_ISSUE_CODES`, `EvidenceLinkRefusal.reason`); the bulk import's are worded in the catalogue (`errors.bulkUploadIssues`, LP4-04), the others until LP4-04 words them.
- **On screen.** No screen LP4-04 has localised shows `error.message`: a failure toasts through `useErrorToast()` (`useStableErrorToast()` inside a `useCallback` an effect depends on) or is worded by its view module, which keeps its own sentence only for the statuses it explains (a 429 or 403 of the bulk import, a 404 of an import batch). `describeApiError` (`apps/web/lib/i18n/errors.ts`): a specific code → its catalogue sentence in the user's language; a generic code → in English the server's own sentence (as before LP3-01), in Turkish the generic sentence with the server's English beneath it (decision K5) for the refusals still generic on purpose (above); a calculation refusal — and `subsidiary_in_use`, `evidence_records_refused`, `evidence_backs_locked_records`, whose English names each dependent or record — shows the server's English sentence in English and, in Turkish, the catalogue's sentence with that English beneath it; a param is worded in the user's language (`period`, `category`, a record's `status`, a `granularity`) and a count grouped; 401, 429 and 5xx → the catalogue's sentence; a network failure → `errors.network`.
- **Numbers (D15).** UI input follows the user's locale — Turkish `1.234,5`, English `1,234.5` — under a strict grammar (`apps/web/lib/i18n/number.ts`): no spaces, exponents or `+`; a separator that cannot be a thousands separator in that locale (`1234.5` or `1.23` in Turkish, `1,5` in English) is refused with a reason, never guessed; a grouped input is echoed as read, and an input the other convention would read as a different number (`1.234`, `45,000`) is echoed with the reading it was NOT; a language change re-renders a typed value from the number it meant. Every quantity field goes through `useDecimalInput` + `DecimalNote` — Data Entry's activity value and its Additional context numbers (LP4-04: saved as JSON numbers; a value saved before as `<input type="number">`'s dot text opens as the number it meant, `storedContextNumber`), the target baseline and target, the intensity denominator — never `type="number"`, whose reading follows the browser rather than the user. The wire value is always a JSON number. **CSV stays dot-only** (the importer's `strictNumber`) and **XLSX numeric cells are taken as numbers**, whatever the user's language; an XLSX *text* cell meets the CSV rule. **The interpretation is previewed (LP4-04):** every accepted row of a dry run (and of an apply) carries `activityValue` and `activityUnit` — the number the server read and stores, the unit in its canonical spelling — and the bulk panel shows them in an "Amount read" column, by the user's locale with every digit kept (`formatReadAmount`), under a note that a file is read dot-decimal; so a Turkish `1.234` meant as a thousand shows as `1,234 kWh` before anything is applied, and a language change re-writes the amount, never changes it. A figure with a comma (`1,5`, `1.234,5`, `1,200`) is refused on its row as `wrong_decimal_separator`, never reinterpreted. **The activity value's bound** (`ACTIVITY_VALUE_MAX`, 1e12) has its own refusal everywhere: Data Entry refuses a larger value in the field (`checkDecimal(…, max)` → `too_large`, "Enter at most 1,000,000,000,000.") before the preview runs; the record and preview routes answer `activity_value_too_large` (400) when it is the body's only refusal (a DTO constraint declared with `codedConstraint`, read by `CodedValidationPipe`; with another field refused too it stays `validation_failed`); a bulk row answers the same code. Display: `formatNumber` (`en` → `en-GB`, `tr` → `tr-TR`); `lib/utils.formatNumber` (comma-only) is gone, and so is every hard-coded `en-GB` in the web app (the dashboard and Emissions in PR B, Review and Audit in PR C). A compact figure (`12.3k` / `12,3 bin`) is `compactTonnes` (`lib/dashboard-view.ts`); a relative time is `formatTimeAgo` (`lib/i18n/relative-time.ts`, date-fns' own locale). English reads as before except at the edges measured in PR A (Intl's rounding of a tie, counts of 1,000 or more now grouped).
- **Dates.** On the wire, timestamps are ISO 8601 UTC and calendar dates `YYYY-MM-DD`; a reporting period travels as its canonical value (`January`, `Q1`, `Annual`) and year as an integer, translated only for display (`periods.values.*`). Screens show dates with `Intl.DateTimeFormat` for the locale's tag in the viewer's time zone. Nothing parses a localised date string; CSV and report exports keep ISO dates.
- **Report and email language (D16 — LP4-01 implements the email half, LP4-03 the reports).** A report's language is chosen at generation (`language` parameter), defaulting to the requester's `profiles.language`, and is recorded in the report's audit row. An email is sent in the recipient's `profiles.language`; an invitation in the language its inviter chose, stored on the invitation. Server-side copy lives beside its module (`apps/api/src/<module>/i18n/{en,tr}.json`) in the same ICU format, rendered with `intl-messageformat` (no React). It is ESM-only, so the CommonJS API loads it through `require(esm)`: Node ≥ 22.12 (CI and the image run Node 22; the prerequisite below and the root `engines` say so since LP4-01's catalogue, `apps/api/src/mail/i18n/`). PDF and XLSX headings follow the report language; **CSV headers stay fixed English machine keys**, CSV numbers stay dot-decimal and XLSX figures stay numeric cells in every language. Never recompute or reinterpret a stored figure for a language. **Auth emails (invitation, password reset) are sent by the API (decision K5, LP4-01):** it mints the link with `auth.admin.generateLink` and sends the TR/EN email itself over SMTP, so Supabase Auth's own templates (which cannot read `profiles.language`) never send one — see [Account lifecycle](security.md#account-lifecycle-lp4-01) and the `transactional-email` skill.
